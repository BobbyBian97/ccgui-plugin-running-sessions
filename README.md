# 运行中会话

在 CC GUI 右侧面板的**「运行中会话」**页签里，跨全部项目实时回显本窗口正在执行的会话轮次：项目、引擎、耗时、**会话标题**与最近活动；卡片带**已读/未读**状态与独立的**「待回复」**状态（模型在等你回答提问 / 批准计划），点击即可跳转到对应会话。

## 功能

- **跨全部工作区**：不管会话属于哪个项目，只要在本窗口执行就会出现，按工作区路径归并
- **卡片信息**：项目名、引擎（Claude / Codex / Gemini / Qwen / Kimi / OpenCode / DeepSeek）、运行时长、会话短 id、标题、最近活动与错误摘要
- **标题行**：与左侧会话列表同源（`custom_title || title`），从宿主会话库只读查询
- **状态**：运行中 / **待回复**（呼吸点）/ 等待授权（呼吸点）/ 正在收尾 / 完成 / 已取消 / 失败；顶部徽标显示运行中轮次数量，有待回复时另显「N 个待回复」
- **待回复（独立状态）**：模型通过 `AskUserQuestion` 提问或 `ExitPlanMode` 提交计划等你确认时，卡片显示紫色的「待回复」，活动行区分「等待你回答：…」与「等待你批准计划：…」。它和「等待授权」是两种独立状态：授权是工具权限被拦，待回复是模型停在交互工具上等你；两者同时出现时以等待授权优先
- **已读 / 未读**：新轮次默认未读（卡片蓝点；已结束的未读卡额外显示「未读」标）。点击卡片打开会话，或点卡片内「标为已读」，整卡转已读
  - 未读轮次**无论处于什么状态都保留**（含已完成/失败）
  - **已读且已结束**的轮次 30 秒后消失
  - 最多保留 200 个轮次（内存兜底），超限时按「已读终态 → 未读终态 → 活动轮次」淘汰最老的
- **点击跳转**：调用宿主 `host:session` 打开对应会话；跳转期间其它卡片禁用，避免重复点击
- **手机 / 外部客户端轮次**：从手机（经中转）或其他客户端发起的轮次没有本窗口的 turn hooks，插件通过引擎进程检测补上：出现在面板并标「外部」章，结束后转为「已结束」（未读照常保留）。「外部」= 本插件实例没有该轮次的事件（页面重载前已在执行的桌面轮次也归此类）。外部轮次同样能识别待回复（Claude 引擎）
- **只读**：不发送消息、不修改会话数据，不在磁盘持久化会话内容

## 安装

- 本地目录：CC GUI → 插件 → 从本地目录安装 → 选择本仓库根目录（含 `manifest.json`）
- 手动：把 `main.js`、`manifest.json` 复制到 `%USERPROFILE%\.ccgui-next\plugins\running-sessions\`，在 `plugins.json` 中登记该插件后重载应用

## 权限说明

| 权限 | 用途 |
|---|---|
| `ui:panel-tab` | 注册右侧「运行中会话」页签 |
| `runtime.events.read` | 订阅轮次开始 / 运行事件 / 结束事件，构建会话卡 |
| `host:session` | 点击卡片时跳转到对应会话（只读） |
| `exec:node` / `exec:python` | 只读查询本机会话库以取标题；`node` 另用于枚举 CC GUI 子进程识别外部轮次，不联网 |

## 数据来源与限制

- **标题**：宿主未开放读取标题的插件 API，插件经 `exec` 授权用 `node:sqlite`（失败回退 `python` 标准库 `sqlite3`）只读打开 `~/.ccgui-next/app.db` 的 `sessions` 表查询 `title` / `custom_title`，与左侧会话列表同源。会话库尚未落行的新会话回退读取 `~/.claude*/projects/*/<sessionId>.jsonl` 的首条 user 消息。缓存：标题 60s、缺失 15s、查询失败冷却 60s。
- **本窗口 + 外部客户端**：本窗口发起的轮次来自 turn hooks（事件级状态）；手机 / 其他客户端发起的轮次宿主不派发 hooks，改由进程检测补录——用 `node` 经 PowerShell CIM 枚举 CC GUI 主进程的子进程，按命令行识别引擎 CLI（`claude.cmd` / `node .../claude-code/cli.js` 等）与 `--resume` / `--session-id` 会话标识；工作区从会话库或 Claude 转录的 `cwd` 解析；新会话首轮没有 `--resume` 时，按「进程启动后新生、`cwd` 属于已知工作区的转录」推断会话标识。面板挂载时每 ~10 秒探测一次（未挂载时 60 秒；探测失败指数退避）。窗口最小化 / 锁屏不停止探测——用手机时桌面窗口常处于隐藏态，跳过会漏掉整段只在手机侧执行的轮次。**进程还在 ≠ 回合还在跑**：宿主用 stream-json 长驻进程承载会话，回合结束后进程可能滞留数小时（CPU 0），所以探测会对 Claude 会话读转录尾部判活——最后一条有效记录是 assistant 的 `end_turn` 终结消息即视为该回合已结束（进程滞留不再显示为「运行中」，标为已读后按 30 秒清理）；长驻进程重新开跑时按新回合重新激活（计时从转录里的新提问起算，未读）。
- **外部轮次的状态粒度较粗**：只有「运行中 → 已结束」两态（Claude 按转录判活，其他引擎按进程存在与否），看不到等待授权/工具活动，也没有退出码；同一会话已有本窗口的轮次时以本窗口数据为准，不重复显示。
- **待回复靠转录尾部推断**：宿主插件总线不下发 question / plan_review 事件，插件只能在面板打开时读 Claude 转录（`~/.claude*/projects/*/<会话id>.jsonl`）的最后 ~256KB，找最新一次 `AskUserQuestion` / `ExitPlanMode` 的 `tool_use`，并判断它之后是否有回答证据（同一 `tool_use_id` 的 `tool_result`、真实用户文本、或后续助手内容；`meta` / 本地命令回显 / 旁支 `isSidechain` 不算）。因此：仅支持 Claude 引擎；面板打开且有活动轮次时约 10 秒探测一次（挂载/回到前台立即补探，失败退避），面板关闭时不探测；回答后最迟约 10 秒回到「运行中」（桌面端正常问答会被运行事件立即解除）；转录缺失或读取失败时保持现状，不会误判为已回答。
- **平台限制**：进程检测依赖 Windows PowerShell 与 PATH 中的 Node 22.3+（用到 `process.getBuiltinModule`）；非 Windows 或缺少可用 Node 时只会显示本窗口轮次（探测失败自动退避，无副作用）。待回复检测同样依赖可用的 Node（仅读转录，不再调用 PowerShell）。
- **加载前已结束的轮次不显示**：插件加载 / 页面重载（F5）前已结束的轮次不会被回溯补录；加载前仍在执行的外部轮次会在下一次探测时出现。
- **已读状态不持久化**：只存在内存中，页面重载后按新事件重建（新轮次仍默认未读）。
- **不联网**：插件不发起任何网络请求。
